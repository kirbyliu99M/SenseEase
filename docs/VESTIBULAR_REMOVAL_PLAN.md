# SEVER-VS-RIP RECOMMENDATION
RECOMMEND: SEVER-ACTIVATION + NEUTRALIZE-TO-DEAD, with a FULL-RIP confined to the App-facing UI surface only.

WHY (safety rationale): This change removes safety-critical, under-protection-harm code. The downstream consumers (B5 gate Cohort.Vestibular arm, B6 classifier vestibular hard-hold, ApplyGateOutcome's liveVest mismatch-abort + hard-hold, selector L9/floor guards, the three chatbot override interceptors) are PURE and HEAVILY TESTED, and every one of their vestibular branches FAILS TOWARD PROTECTION. Once activation is severed — i.e. `_vestibularProtection` can never become true and `snap.Vestibular` is constant-false — these branches become statically unreachable but remain correct-by-construction. Ripping them instead would be a large, churning, integrity-bearing diff (it ripples through AdaptationCommitRequest, SnapshotForAdaptation, the classifier signature, and the JUST-SHIPPED B6 Stage 4b tests at commit 55a5358) for ZERO runtime benefit and NONZERO risk of a half-severed mismatch (e.g. pinning snap.Vestibular false but leaving liveVest readable could mis-fire the mismatch-abort). The smaller diff is the safer diff here.

WHY the UI is full-rip (the exception): the one-time prompt bar and the Settings toggle are pure presentation with no safety logic. A hidden-but-live toggle is a regret vector, and the prompt bar literally asks a clinical-diagnosis question ("Do you have a vestibular/dizziness diagnosis?") that directly contradicts the new non-clinical scope — leaving it dead would be worse than removing it.

WHY enums/DTO fields stay: deleting Cohort.Vestibular, MedicalAdvisory.Vestibular, or the persisted DTO fields would break back-compat deserialization of existing on-disk snapshots AND make the graceful migration impossible to even detect (the migration READS VestibularProtectionEnabled). An always-false bool / never-emitted enum member is inert; keep them through at least one upgrade cycle.

NET: activation impossible, existing protected users gracefully re-homed into the strongest surviving profile, the safety machinery preserved and documented-dead, smallest blast radius. A pure-cleanup sprint to rip the dead branches can be scheduled LATER once migration has drained all legacy snapshots (after N releases) — explicitly NOT part of this removal.

DUAL-SIGNAL NEUTRALIZATION (both must clear, on the SAME persist):

  2. The advisory — BuildProfileSnapshotCore:2251 writes null (flag false).
