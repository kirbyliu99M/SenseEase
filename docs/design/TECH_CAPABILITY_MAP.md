# SenseEase Technical Capability Map — Signals, Actuators, State, Latency, Headroom

> Scope: the real-time sensing → inference → rendering → feedback loop as it exists at Pre-Alpha v0.11.1. Every claim is cited to `file:line`. The immersive-experience pillar must be built ONLY on the capabilities marked **REAL** below; capabilities marked **HEADROOM** exist in code but are not yet surfaced.

## 4. Latency + Performance Envelope

- **Runs at ~15 Hz:** WGC capture + MAD diff + leaky integrator + tier update + habituation step + profile persistence (all inside one `Update` tick).
- **Runs at 30 Hz:** cursor velocity provider (when used); Driver/Passenger at 1 Hz.
- **Runs at display refresh (up to 165 Hz):** head-pose mask follow via `CompositionTarget.Rendering` with 15 ms half-life interpolation, ~0.17% of one core (`MainWindow.xaml.cs:446`). This is the **only existing frame-rate-decoupled animation path** and is the proven foundation for any immersive loop.
- **Heavy operations:** WGC GPU→staging `CopyResource` + CPU `Map` + 160×90 nearest-neighbour downsample every 66 ms (`WgcSensingProvider.cs:586`) — full-monitor readback is the iGPU bottleneck and the known stutter source; per-tick allocations are aggressively eliminated (ping-pong buffers `:109`, cached callbacks `:156`, index tables `:117`). MediaPipe sidecar inference (separate Python process, own webcam, ~15 Hz) and llama-server (separate Vulkan process, VRAM-resident, seconds per reply) are isolated from the UI thread.
- **Mask color recompute** is skipped when the packed RGBA key is unchanged (`:401`); brush mutation is in-place (no per-tick allocation).
- **Headroom for an immersive loop:** the 165 Hz `CompositionTarget.Rendering` path already exists and is cheap. A real-time immersive renderer could afford continuous brush/gradient/color tweening at refresh rate; what it CANNOT afford is more full-monitor WGC readbacks (already the ceiling on iGPU) or synchronous LLM calls on the render path.

## 5. Headroom — Existing-but-Under-used Capabilities (raw materials for immersion)

1. **Two parallel mask-drive paths already exist.** The engine writes `HeadGazeX/Y/HeadTrackingActive` into `SenseState` at engine tick (`MainViewModel.cs:1409`) AND a separate 165 Hz render loop pulls the reader directly (`MainWindow.xaml.cs:504`). The high-frequency path (`UpdateHeadGazeCenter`, `OverlayWindow.cs:542`) is a clean, proven entry point for ANY smooth real-time mask motion — not just head pose.
2. **Webcam luma is computed every frame and thrown away.** `HeadPoseSample.Luma` (0–1 ambient brightness, `head_tracker.py:167`) crosses the IPC boundary but has zero downstream consumers — a ready-made ambient-light signal for adaptive dimming (the abandoned `WebcamLuxProvider`).
3. **Raw yaw/pitch degrees + roll are decomposed every frame** but only emitted in `--debug` and never carried on the public record (`SidecarHeadPoseReader.cs:656`). Head tilt/roll is available for richer gaze interaction if the schema lock is lifted.
4. **Head-pose mask-follow only operates in the engine-tick state path for `HeadTrackingActive`,** but the Balanced-mode [0.10, 0.90] clamp means the periphery is never fully cleared — FullFollow + escape-hatch are the only ways to reach screen corners (`OverlayWindow.cs:564,481`).
5. **Spike detector is fully built but its only consumer is the pop-up/chatbot bubble,** suppressed during demos, with a 30 s cooldown (`PressureSpikeDetector.cs`, `MainViewModel.cs:1422`). `LastNormalizedSpike` (0–1 intensity) is unused by any visual.
6. **Chatbot can emit structured write-side tokens** — `[PROFILE_OVERRIDE]`, `[OBSERVATION_ADD]`, `[RESUME_ACKNOWLEDGE]` (`MistralChatbotService.cs:100`) — and four live shader knobs (fov/mask_depth/grid_visibility/feather), but the UI only surfaces fov-delta + proposal cards. Mask-depth/feather adjustments are wired end-to-end yet never shown.
7. **Idle-ms is sampled live at 1 Hz** (`UserActivityModeDetector.IdleSampled`) but collapsed into a binary Driver/Passenger; the continuous presence/attention signal is discarded.
8. **VIMS tier (1–10) is a smooth, debounced, comfort scalar** that already drives mask alpha, grid, bar, and tray in lock-step via one shared table — the natural single source of truth for an immersive comfort-state visualization.
9. **Pressure is unbounded** (>300 observed) but every UI clamps or buckets it; the raw integrator value carries far more dynamic range than any current surface exposes.
