### architecture
SenseEase is a Windows WPF .NET 8 app (net8.0-windows10.0.19041.0, self-contained, fully local/no egress) intended to reduce Visually-Induced Motion Sickness on desktop monitors. Authoritative architecture doc is docs/TECHNICAL_WHITEPAPER.md (2026-06-08 "Alpha-2 engine-integrity" revision). Data flow: WGC capture 15 Hz → 160×90 greyscale → MAD × normFactor 4.0 → 3-tap median → clamp[0,150] → EMA α=0.55 = OFI. Cursor provider (30 Hz) is fallback; GetLastInputInfo classifies Driver (OFI×0.25) vs Passenger (weight 2.0) — 8× asymmetry, declared working hypothesis. Noise-gated (8) leaky integrator (decay 0.965/100 ms, τ≈2.81 s, quadratic 0.0008) yields pressure P. Raw TriggerPressure=85 drives mask hysteresis (on ≥85, off <72.25, 8 s cooldown), continuous FOV radius (100→35 at trigger→15 at P=136), and native 1–12 level projection with hysteresis (UI shows 5 cool-blue 動態感 bands; deliberately no alarm-red). EffectiveTrigger (85/personal_scale; vestibular override 50) feeds ONLY habituation spike/calm checks, Adaptive-Fit stats, and DisplayStressPercent — intentional asymmetry, documented load-bearing. HabituationEngine adds earned _offset to FOV radius (graded exposure); strikes halve it; top-band pause exits only via user confirm. Alpha-2 core is LIVE (both flags ON since c1461a9): auto-profiling seeds fresh users at L5/TYPICAL (explicit Q1–Q5 calibration DELETED, commit 3131387); deterministic Adaptive-Fit selector over a 10×5 (Band,Shape) 50-set grid, Set0 byte-identical to legacy engine, confidence-gated, cooldown state machine, 24 h propose-confirm for cross-band moves; vestibular protection via one-time opt-in prompt + permanent Settings toggle. User-Model UM1–UM5: numeric-only behavior_log.jsonl daily aggregates, schema-v3 monthly observation buckets, [behavior_trend] chatbot block. Rendering: click-through overlay (radial peripheral attenuation mask + world-locked Chang–Hain anchor grid), ambient bar, tray, notification card; feathering halo fixed by asymmetric radius envelope (attack 25 ms/release 600 ms), P1 shipped/UVHS-confirmed. Chatbot: lazy-loaded Ministral 3B via side-loaded Vulkan llama-server on 127.0.0.1:8181 (api-key, --no-webui); pipeline order: slash-command lexicon → Core SafetyFloor → LLM → parser → 5-rule Processor → card → defensive Applicator. ### design-ux
SenseEase is a WPF tray-resident "screen visual-comfort aid" for VIMS/migraine/vestibular-sensitive users: WGC optical-flow sensing → leaky-integrator pressure → comfort scalar driving a radial FOV dimming mask, plus opt-in webcam head-tracking (local sidecar), a local Ministral-3B assistant, and a weeks-scale habituation offset (_offset) that gradually relaxes protection.

Design north star (UIUX_UPGRADE_PLAN, 2026-06-05): "the app must embody the calm it sells" — Apple HIG Clarity/Deference/gentle Depth, accessibility-as-the-product, litmus test "would this calm a nauseated person?". docs/design/LOCKED_DIRECTION_ALPHA1.md is the declared source of truth: one posture, "Quiet Guardian that Learns You" — app disappears into the OS, answers only "Am I protected and is it working?" in plain language (never a number), one effortless action ("Ease my view now"), honest fault surfacing (liveness contract: Protecting/Steady-watching/Paused-by-user/Faulted; Paused=dashed vs Faulted=solid outline must never be confusable; ≤~5s worst-case dead-pipeline-renders-healthy). ### features
SenseEase: local-only Windows WPF app mitigating visually-induced motion sickness (VIMS). WGC screen capture computes optical-flow pressure; HabituationEngine earns a FOV-relaxation offset during sustained calm; an overlay dims the periphery. UI: persistent 4-dip bar, tray, notification card (TierColorPalette = sole tier-to-color source; always-on mask invariant: any visible UI on the captured monitor must register SetMonitorExcludeRect). On-device Ministral 3B (loopback llama-server) reads a [habituation_state] block and proposes engine changes via [PROFILE_OVERRIDE] blocks — strictly proposer-not-actor: parse → 5-rule Processor validation → user-confirm Card → Applicator apply-time re-check (3 intercept rules) → single locked engine write path. Calibration (live today): post-demo 5-card buttons first run, 8-turn LLM dialog subsequently; CalibrationProcessor derives profile (RESILIENT/TYPICAL/SENSITIVE), personal_pressure_scale [0.7,1.5] applied as effectiveTrigger=85/scale (consumed only by spike-recurrence + calm checks; mask/FOV/tier read raw 85). Head tracking: opt-in (default OFF); Python sidecar emits only derived scalars (t_ms, cx, cy, luma, face_detected, face_present; yaw/pitch debug-only). OBS-3 forbids landmarks/frames/network/file writes — any violation is a release blocker.
